# Kinema brand guidelines

Status: implemented artwork in `crates/kinema-desktop/assets/brand/`, regenerated by
`packaging/generate-icons.py` and checked by `packaging/test_assets.py`. Windows
EXE resources, macOS bundles and per-window icons outside X11 are still
unqualified (see [packaging notes](../../packaging/README.md)).

## The mark

A lowercase **k** whose arm and leg merge into a right-pointing **play** arrow. The
stem rises above the arm (an ascender), so it reads as a letter first and a play
button second. The 2026 redraw replaces the traced bitmap outline with clean
construction that follows the historical shape:

- Units are relative to glyph height `H`. The stem is `0.228 H` wide and spans the
  full height. The arm cap starts `0.145 H` below the top.
- The upper arm's inner and outer edges are parallel and run at 45°. The arrow
  edges run at ±35.5° and meet at the tip `(0.825 H, 0.54 H)`. The leg edges are
  parallel at 56° and end on the baseline.
- Corner radius is `0.02 H`; the tip uses `1.6×` and the arrow notches use `0.6×`.
- On tiles the glyph is optically centred: its box is nudged right by about 1 %
  of the tile, because the stem carries more visual weight than the tip.

## Colours

| Token | Hex | Use |
| --- | --- | --- |
| Kinema orange | `#FF7A45` | App tile, player glyph and seek progress; same as the Dark UI `accent` |
| Ink | `#382218` | Player tile; warm near-black that pairs with orange |
| White | `#FFFFFF` | Glyph on orange, seek-bar knob |
| Symbolic fallback | `#232629` | Only before a desktop recolours the symbolic icon |

White on orange is 2.6:1. That is fine for the large logo shape, but **not** for text
or controls. UI text and controls use the `accent`, `on.accent` and `accent.text`
tokens in [desktop v3](desktop-v3.md#21-color--cinema-dark-default). Orange on ink
is 5.8:1.

## Variants

| Variant | Source | Construction | Where |
| --- | --- | --- | --- |
| App | `dev.tlmtech.kinema.svg` | 1024 grid; 896 px orange tile (64 px margin, 192 px radius); white glyph `H = 624` | Launcher, main window, Linux hicolor, ICO |
| App 16 px | `dev.tlmtech.kinema-16.svg` | 16 px grid; 14 px tile, 3 px stem on whole pixels, simplified notches | 16 px PNG and ICO slot |
| Player | `dev.tlmtech.kinema-player.svg` | Same tile on ink; orange glyph `H = 544` raised to fit a seek bar (58 % progress, white knob) | Player windows (X11) |
| Player 16 px | `dev.tlmtech.kinema-player-16.svg` | Hinted glyph plus a 1 px seek bar with no knob | 16 px player PNG |
| Symbolic | `dev.tlmtech.kinema-symbolic.svg` | 16 px grid; `currentColor` plus KDE's `current-color-scheme` hook; no tile | Panels, monochrome contexts |
| macOS | `dev.tlmtech.kinema-macos.svg` | Apple grid: 824 px body inset 100 px, 185 px radius, 10 px drop shadow | ICNS only |

The player variant reverses the colours instead of shrinking the mark into a
screen frame. This keeps the K the same size as in the app icon and keeps the two
icons distinct even at 16 px.

## Usage rules

- Keep at least one-eighth of the mark's width as clear space around it. Do not
  rotate, outline, add gradients to, or recolour the mark beyond the variants above.
- Use the app tile at 16 px or larger. Below that, or for monochrome contexts,
  use the symbolic glyph.
- Never use the player variant as the application or launcher icon; it only marks
  player windows.
- The artwork is Apache-2.0 with the source code. No separate trademark policy
  exists yet, so this document does not restrict the name or mark for forks.

## Editing

Edit the SVG sources. Keep the geometry and the `-16` hinted sources in step: the
`-16` stems sit on whole pixels. Then run:

```sh
python3 packaging/generate-icons.py
python3 packaging/test_assets.py
```
