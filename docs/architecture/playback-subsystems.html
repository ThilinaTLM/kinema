A play action flows through five cooperating subsystems. The downloader picks a backend (Torrent, Real-Debrid, or AllDebrid) and creates an AssetSession. The torrent engine (libtorrent) or a debrid resolver supplies bytes. The local streaming server (127.0.0.1) exposes those bytes as an HTTP URL with Range support. The embedded mpv player consumes that URL and emits time-pos updates. The progress tracker debounces, throttles, persists, and decides when a title is finished — and, for series, what plays next.

Every play action — whether the user clicked a stream row, hit "Resume" on Continue Watching, or auto-advanced to the next episode — converges on the same pipeline:

A five-layer pipeline: sample → debounce → throttle → persist → resolve. time-pos is sampled by mpv, debounced at 250 ms inside MpvVideoItem, then throttled to a 5 s persistence cadence in HistoryController. End-of-file finalizes the row with a finished flag derived from completion percentage and chapter metadata.

Persists every ~5 s if Δposition warrants it; ignores updates inside the first 0.5 % of duration. Captures the stream reference (infoHash, releaseName, resolution, size, provider) once at play time — never overwritten by later position ticks, which is what makes Continue-Watching resume across different releases work.

Layered resolution: manual Watched override > manual Unwatched override > history.finished. Users can flip status without re-watching; auto-finish never destroys an explicit override.

For series, derives previous/next episode files from the active session via DownloadManager::filesForInfoHash() (covers both libtorrent and debrid-cached lists). Emits packAdjacencyResolved(nextAvailable, S, E) one-shot when a season pack actually carries the next episode.

Sentinel timer that fires if loadfile doesn't progress to file-loaded within the configured window — surfaces a passive error so the UI can recover instead of spinning forever on a dead source.
