The strongest fit is a session-centric event-driven architecture: every play request creates or resumes a PlaybackSession that accepts commands, emits typed events, and is governed by explicit state machines. Around that, use ports/adapters for mpv, local HTTP, torrent, debrid, subtitles, MPRIS, tray, and persistence. Avoid a global app-wide event bus; use a small typed event stream scoped to the playback subsystem.

Model playback as a long-running session process. UI sends commands such as PlayStream, Pause, Seek, SaveOffline, SelectSubtitle, and Stop. The subsystem emits facts such as PlaybackStarted, PlayableUrlReady, BufferingChanged, PositionTicked, DownloadProgressed, SubtitleAttached, and PlaybackEnded. Independent consumers update history, MPRIS, subtitles, downloads UI, tray state, and series auto-next.

Decouples producers from consumers. mpv no longer directly drives history, MPRIS, subtitle state, and series logic through controller chains; it emits playback events. Makes lifecycle rules explicit: loading, buffering, playing, paused, seeking, ending, failed; transfer states such as resolving, streaming, downloading, paused, completed. Keeps infrastructure replaceable: embedded mpv, external player, local HTTP gateway, torrent engine, debrid HTTP, OpenSubtitles, MPRIS, tray, SQLite stores.

This subsystem is already asynchronous and event-like: mpv emits property changes, libtorrent emits alerts, LocalMediaServer responds to Range requests, debrid resolvers complete later, downloads progress over time, and history/MPRIS/subtitles/tray are all observers of playback state. The missing piece is not event-driven behavior itself — Qt signals already provide that — but an explicit domain event model and session state that prevent point-to-point coupling.

Good for object-to-object notification, but dependencies become implicit and hard to trace when controllers connect directly to other controllers. Facts named in playback language, carrying a sessionId, assetId, PlaybackContext, stream reference, timestamp, and reason. Consumers subscribe to facts, not concrete objects. Some classes both decide workflow and react to player/network events. One process manager owns the workflow. A session is the owner of one user-visible playback attempt. It has a stable sessionId, accepts commands sequentially, owns current context, current asset, selected backend, local URL, loaded player state, transfer state, and next/prev episode targets.

This is close to the actor model, but implemented with Qt/QCoro: one QObject, one thread affinity, one command queue, epoch guards for async work.

Use a small playback-subsystem event stream. It is not a global app event bus. Events are typed C++ structs or std::variant alternatives, and every event includes correlation identity.

Examples: PlaybackRequested, SourceResolving, PlayableUrlReady, PlayerLoaded, PositionTicked, TransferProgressed, SubtitleAttached, PlaybackEnded, PlaybackFailed.

State machines make race handling visible. For example, an mpv end-file: stop while replacing a URL is ignored because the state machine is in ReplacingSource, not because a scattered boolean happened to be set.

Keep policies pure: backend selection, file selection, watched thresholds, resume clamping, and piece-priority plans. Infrastructure remains imperative and asynchronous, but decisions become easy to test.

Embedded playback PlaybackSession sends PlayerPort::play; mpv adapter emits PlayerLoaded, PositionTicked, PlaybackEnded. mpv is one adapter; business logic does not depend on PlayerWindow.
Local streaming server Gateway exposes ByteRangeSource; emits RangeRequested, RangeReady, RangeFailed telemetry. Server does not know torrent/debrid/download manager.
Torrent engine Torrent source handles OpenSession; emits transfer and file-catalog events. Libtorrent alerts stay inside torrent adapter; session sees generic facts.
Debrid services Debrid source resolves magnet/file/hoster URL; emits same session events as torrent source. Playback and series auto-next do not care whether bytes are RD, AD, or torrent.
Downloads UI Projection from TransferProgressed, TransferPaused, TransferCompleted, TransferFailed. Downloads page becomes a read model, not an owner of transfer rules.
History / Continue Watching Projection from PlaybackStarted, PositionTicked, PlaybackEnded. Progress persistence no longer wires directly to player window.
Subtitles Subtitle service reacts to PlaybackStarted, MoviehashComputed, TrackListChanged; command AttachSubtitle. Subtitle logic does not depend on playback controller internals.
MPRIS / tray Projection from PlaybackStateChanged, PositionTicked, MetadataChanged. Desktop adapters become observers of session state.
Series auto-next Session/catalog events populate next target; PlaybackEnded(eof) triggers PlayStream(next). No direct dependency on both downloader and torrent engine.
Ports/adapters, use cases, pure policies, stream gateway, media source abstraction, and a recommendation to avoid broad controllers. The previous proposal should explicitly name PlaybackSession as the central process manager and define a typed event stream plus state machines. That is the main architecture-level improvement beyond ordinary decoupling. Do not add a global pub/sub bus for the whole app. Do not persist all runtime events. Do not force discovery/search/library into this architecture work.
OptionFitRecommendation
Qt signals only Already used; low friction, but point-to-point coupling remains hard to reason about. Keep for adapter edges, but wrap important facts as typed domain events.
Global event bus Decouples quickly but often hides dependencies and makes ordering/debugging hard. Avoid.
Scoped typed event stream Good fit for playback subsystem: clear contracts, correlation IDs, testable event sequences. Use.
Event sourcing Useful when audit/replay is a product requirement. Here it adds storage complexity. Do not use initially.
Actor model Good conceptual fit for long-lived playback/transfer sessions. Use the idea with QObject/QCoro, not a new actor framework.
Statechart library Could help if lifecycle complexity grows; introduces dependency/learning curve. Start with explicit enum + transition table; consider Qt SCXML or Boost.SML later.
Do this without moving behavior. Have current controllers emit a small event stream in parallel with existing signals. It initially delegates to current StreamActions, DownloadManager, PlaybackController, and HistoryController. Then behavior moves inward. Convert history writes to consume PlaybackStarted, PositionTicked, and PlaybackEnded. Keep public controller APIs for QML compatibility. They subscribe to session/player events instead of directly observing concrete controller chains. Once events reveal the real lifecycle, codify transitions and delete scattered booleans/epoch rules where the state machine makes them unnecessary.
